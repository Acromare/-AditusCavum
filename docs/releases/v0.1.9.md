# AditusCavum v0.1.9

## Real incremental streaming

Previously, `stream()` waited for synchronous chat to finish and emitted the entire answer once. v0.1.9 sends `stream: true`, reads the provider's UTF-8 Server-Sent Events as they arrive, and emits text deltas through `Flux<String>`.

```java
return assistant.stream(conversationId, message);
```

The application still owns its HTTP endpoint. Return the publisher with `text/event-stream`; the browser must consume SSE incrementally. See the [integration guide](https://github.com/Acromare/-AditusCavum/blob/v0.1.9/docs/streaming.md) for a POST endpoint, terminal events, error handling, and browser requirements.

## Implementation details

- Added `ChatModel.stream(List<ChatMessage>)` and `AditusAssistant.stream(conversationId, message)`. Stateless and conversation streams both include the configured system prompt.
- The SSE reader handles UTF-8, LF/CRLF, comments, and multi-line data events without buffering the full answer. Blocking network reads run on Reactor's bounded-elastic scheduler; cancellation closes the response body. An idle event stream times out after two minutes.
- Tool-call fragments are accumulated by call index, including interleaved calls. Completed calls are validated before execution, their results are appended to model context, and another streaming request continues the answer.
- Only successfully completed conversation streams save the user message and combined assistant text. Errors and cancellation do not commit partial turns.
- HTTP errors, provider error events, malformed payloads, truncation, and missing completion markers propagate as stream errors. No automatic retries are introduced.
- Corrected the tool-round boundary so tools cannot run beyond the configured limit, including synchronous chat. A limit of zero now prevents all tool execution.
- Corrected synchronous exception handling: ordinary I/O failures no longer incorrectly mark the executing thread as interrupted.
- Requests without tools omit empty `tools` and `tool_choice` fields.

## Validation

Fourteen automated tests pass, including ten streaming tests backed by a local HTTP server. Coverage includes first-chunk delivery before server completion, UTF-8/multi-line SSE, interleaved tool fragments and result handoff, invalid arguments, tool-round limits, HTTP/provider errors, premature EOF, cancellation cleanup, system prompts, conversation isolation, and the lazy fallback for custom chat-only models.

A live Qwen smoke test returned 19 chunks: the first arrived at approximately 0.97 seconds and the stream completed at approximately 3.32 seconds. Two conversation-memory entries were committed. Timing varies with the provider and network.

## Upgrade and compatibility

```xml
<dependency>
    <groupId>com.github.Acromare</groupId>
    <artifactId>-AditusCavum</artifactId>
    <version>v0.1.9</version>
</dependency>
```

Java 17+, Spring Boot 4.1.1, and existing dependencies are unchanged. The v0.1.8 consumer-configuration fix remains in place. Synchronous `chat()` remains available.

Custom models overriding only `stream(String)` should also override the new message-list overload to support streaming through `AditusAssistant`; otherwise the compatible fallback emits one complete `chat(messages)` result lazily.

Serialize active requests for the same conversation ID. Cancellation cannot roll back tool side effects, and retrying a whole turn can repeat them. Providers must supply OpenAI-compatible SSE with `finish_reason` and `[DONE]`; `length` and `content_filter` endings are surfaced as incomplete-stream errors. Configure Spring MVC async timeouts and proxy buffering in the consuming application as needed.
