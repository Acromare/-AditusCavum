# AditusCavum v0.2.2

Welcome to v0.2.2: the release where AditusCavum stops feeling like glue code
and starts feeling like a small, ready-to-enjoy AI runtime. Add the dependency,
declare your knowledge, and let the framework carry the repetitive work while
your Java code stays focused on the application.

This release turns the core model client into a ready-to-use Spring Boot
assistant while preserving the existing Java APIs.

## New capabilities

- `@AditusSylva("classpath:knowledge")` automatically loads text resources, splits them into chunks, and adds the most relevant chunks to each chat or stream request.
- `KnowledgeRetriever` is a public extension point. The default implementation is dependency-free lexical retrieval; applications can replace it with an embedding or vector-store implementation.
- A default web API is registered when the application is a web application:
  - `POST /aditus/api/chat`
  - `GET /aditus/api/stream`
  - `DELETE /aditus/api/conversation/{conversationId}`
- Bundled browser pages are available at `/aditus/` and `/aditus-console/`. The console reports model, tool, and knowledge status without exposing credentials.
- `@CavumOperis` provides a concise tool declaration. Existing `@MarkTheRuins` and `@Need` declarations remain valid.
- Conversation operations are serialized per conversation ID. A completed turn is stored atomically, and failed or cancelled model calls do not pollute memory.
- Model settings can be supplied through `ADITUS_API_KEY`, `ADITUS_BASE_URL`, `ADITUS_MODEL`, and related environment variables without an AditusCavum YAML block.

## Complete change list

The release also includes the following implementation-level changes:

- Added public `AditusSylva`, `KnowledgeDocument`, `KnowledgeLoader`,
  `KnowledgeRetriever`, and `InMemoryKnowledgeRetriever` APIs.
- Added `AditusChatRequest` and `AditusChatResponse` DTOs for the default web
  contract.
- Added conditional default Controller and console beans that respect
  `aditus-cavum.web.enabled`, `aditus-cavum.web.console-enabled`, and the
  configurable `aditus-cavum.web.path` prefix.
- Added bundled static browser pages under `/aditus/` and
  `/aditus-console/`.
- Added the `@CavumOperis` annotation while keeping the older tool discovery
  annotations source-compatible.
- Added environment aliases while retaining the legacy `ADITUS_MODEL_*`
  names; explicit Spring configuration remains higher priority.
- Added `KnowledgeRetriever` injection to both blocking and streaming assistant
  flows, with configurable `knowledge-top-k`.
- Added per-conversation locking and atomic turn append behavior to prevent
  history corruption during overlapping calls.
- Changed the build baseline to Spring Boot 3.2.5 and Java 17 so consumer
  projects can supply compatible Boot 3 or Boot 4 dependency management.

## Compatibility

- JDK 17+
- Maven 3.8+ and Maven 4.x
- Spring Boot 3.2+ and Boot 4.x consumer applications
- MyBatis-Plus 3.x and 4.x as an independent application dependency; AditusCavum does not bind to MyBatis-Plus

## Upgrade

```xml
<dependency>
    <groupId>com.github.Acromare</groupId>
    <artifactId>-AditusCavum</artifactId>
    <version>v0.2.2</version>
</dependency>
```

Existing v0.2.1 clients and services require no migration. To enable the new RAG flow, add `@AditusSylva` and place knowledge files under `src/main/resources/knowledge/`. Disable the built-in web surface with `aditus-cavum.web.enabled=false`, or disable only the console with `aditus-cavum.web.console-enabled=false`.
